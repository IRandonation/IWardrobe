# M0 与人工衣橱子集：本机验收

日期：2026-10-13，Asia/Shanghai。代码仍在本机工作区，尚未提交 Git、推送或部署 NAS。

## 交付范围

React / TypeScript 响应式页面、FastAPI、PostgreSQL 迁移与持久数据、独立账号、Argon2id 密码、服务端会话、CSRF/Origin、私有图片、后台缩略图和任务重试。人工衣橱包括上传、手填、编辑、搜索、分类、排序、收藏、穿着次数、待洗/洗净及收纳/恢复。

生成了 4 张透明背景 PNG，文件和提示词在 `fixtures/demo/`。同一份夹具按账号各自导入，所有单品保留演示标记。生成图片不能作为自动抠图或真实材质识别的效果证明。

## 环境

| 项目 | 实际值 |
| --- | --- |
| 前端 | Windows、Node 24.18.0、pnpm 11.21.0、Vite 7.3.7 |
| 后端 | 项目隔离的 CPython 3.12.15、FastAPI 0.143.0、SQLAlchemy 2.1.4 |
| 数据库 | WSL Ubuntu 22.04 内独立目录的 PostgreSQL 16.15，127.0.0.1:5433 |
| 队列 | 同一专用目录的 Redis 6.0.16，127.0.0.1:6380；arq 0.28.0 |
| 网页 / API | 127.0.0.1:5173 / 127.0.0.1:18765 |
| 数据 | 数据库在 WSL 专用用户目录；原图/缩略图在 `.local/data/` |

依赖版本由 `pnpm-lock.yaml` 和 `backend/uv.lock` 固定。Redis 7 Compose 路径作为可选配置提供，本次实测使用 Redis 6.0.16；WSL 便携包启动日志有 cjson 动态模块加载提示，本项目已验证的 arq 任务路径不依赖该模块，不将本机运行时当作生产环境。

## 验证结果

| 验证 | 结果与覆盖 |
| --- | --- |
| `pnpm build` | TypeScript 检查与 Vite 生产构建通过 |
| `pytest` | 10 项通过，约 10 秒；连接真实 PostgreSQL，恢复测试连接真实 Redis |
| Playwright 桌面 | 1440×1080，通过，14.4 秒 |
| Playwright 手机视口 | 390×844，通过，18.8 秒 |
| 完整服务重启 | API、worker、网页、PostgreSQL、Redis 全部停止后重新启动，通过 |

后端测试覆盖：其他账号的衣物/图片/任务不可访问或修改；CSRF 和来源校验；退出后旧会话失效；无效图片不创建半成品记录；待洗衣物不能记为已穿；旧版本编辑返回冲突；演示导入幂等；重复执行任务不重复计数；失败后重试、旧派发失效、过期租约重派发；停用账号不发布新图片；数据库复合外键拒绝跨用户关联。

两套浏览器测试均使用全新专用账号完成：登录 → 空衣橱 → 导入 4 件 → 再导入不重复 → 实际 worker 完成任务 → 原图/缩略图可显示 → 收藏 → 搜索 → 穿着一次 → 待洗 → 洗净 → 编辑备注 → 上传新照片 → 刷新保留 5 件 → 未登录不可读图片 → 退出登录。两套视口均无横向页面溢出、无浏览器页面异常。

重启验证保留了 `demo` 的 4 条完整衣物记录、4 张原图 SHA-256 和已有登录会话。worker 停止期间另建专用测试账号并排队一张图片，数据库和 Redis 重启后由 worker 自动补派发、生成缩略图。机器可读结果在 `.local/restart-validation.json`。

验证中修复：未登录初始化清理正在观察的会话 Query 导致一直加载；Windows 路径传入 WSL 时的反斜杠转义；默认 API 端口与现有程序冲突。详情备注的自动化定位改用 textbox 可访问名称。已去掉外部字体请求，使本机页面不依赖字体网络加载。

## 验证边界

- 手机测试是 Chromium 移动视口和触摸模拟，没有真实手机相机、iOS/Safari 或局域网 HTTPS 验收。
- 未接入 AI 识别、自动抠图、图片正面重建、天气、推荐和偏好学习；未消耗用户项目模型凭据。
- 未验证 Docker / NAS、备份恢复、长期定时任务、生产安全加固或大量衣物性能。
- 当前是回环地址开发 HTTP；登录 Cookie 的 Secure 标志需要在后续 HTTPS 入口配置时启用。
- 后端测试有 Starlette 对 httpx 测试客户端的弃用提示，不影响本轮通过结果。
