# BiRefNet Lite CPU 抠图：本机实现与验证

日期：2026-10-22。范围为 Windows 本机功能，尚未验证 NAS 部署。

## 已实现

- 上传默认使用 BiRefNet Lite，可取消自动抠图；详情固定使用此模型。
- 后台任务按 thumbnail / cutout 类型分发；模型任务串行执行，失败可重试，相同照片/模型不重复排入活动任务。
- 保留原图与 BiRefNet Lite 最近成功结果；详情中切换预览、查看耗时、选为展示图或恢复原图。
- U²-Netp 已停用：不能新建、重试或选择其结果；旧展示选择回退原图，历史任务及成功 PNG 链接仍可读取，缓存和文件不删除。
- 展示选择按模型保存；再次运行所选模型成功时使用其最新结果，失败仍保留之前成功结果。历史成功文件暂不自动删除。
- 图片和任务均按账号隔离，派发代号失效或账号禁用后不能发布结果。
- 输出 1024×1024 RGBA PNG：EXIF 方向校正、保留原图可见颜色与既有透明度、生成 mask、裁边、等比例缩放居中。无衣物补全或生成式正面重建。
- 独立推理子进程，600 秒处理超时；arq 任务超时 660 秒、任务租约 720 秒。Windows 终止整个进程树，避免 Python 虚拟环境启动器的子进程残留。

## 收敛为 BiRefNet Lite 后的验证

- 后端 25 项测试通过（抠图 15 项、原工作流 10 项），使用专用 PostgreSQL 测试库；模型推理在这些测试中替换为写入真实 PNG 的测试函数。
- 新增兼容性回归：旧模型请求返回 422；历史任务列表和图片链接可读且校验归属；旧展示选择回退原图；旧失败任务不可重试、旧排队任务不会运行推理。
- 后端 Ruff E/F、Python 语法检查及前端 TypeScript/Vite 构建通过；OpenAPI 和前端类型已重新生成。
- 单模型浏览器流程通过：桌面 44.8 秒、手机视口 39.4 秒，真实 API、队列和 BiRefNet Lite 推理；两次示例处理约 25.7 / 26.0 秒。验证默认勾选自动抠图、无模型选择器、结果采纳、恢复原图、未保存备注及保存刷新；截图检查无横向溢出或页面 JS 错误。使用生成图片验证功能链路，不代表真实照片效果。

## 真实照片推理观察

另外读取 [cloth-segmentation 官方仓库的公开示例](https://github.com/levindabhi/cloth-segmentation/blob/main/assets/000.png)，仅取左半原始穿着照作本机测试。样本和输出仅存于被忽略的 `.local/data/validation/`，不随本仓库分发。

两模型都在 CPU 上输出有效的 1024×1024 RGBA PNG，alpha 范围为 0–255。在权重已经缓存的情况下，这一张照片的单次记录为：

| 模型 | 处理耗时 | 目视观察 |
| --- | ---: | --- |
| U²-Netp | 4.023 秒 | 保留人物和衣物，裙摆周围残留部分地面 |
| BiRefNet Lite | 25.932 秒 | 该样本裙摆周围背景更干净，同样保留人物 |

耗时含子进程内库导入、模型初始化和图像处理，不含排队；首次下载还会增加耗时。这是本机单样本观察，没有统计 P50/P95、峰值内存或服装评测集指标，不能推广为 NAS 性能或总体质量排名。两个模型是通用前景抠图，穿着照保留人体属于当前功能边界。

## 运行与复现

- Python 3.12，`rembg[cpu]==2.0.86`，本次锁文件的 ONNX Runtime 为 1.31.0；使用 `CPUExecutionProvider`。
- 缓存根目录默认 `.local/models/`；当前使用 BiRefNet Lite ONNX 224,005,088 字节。首次由 rembg 下载，照片不发送到第三方；之前试用的 U²-Netp 缓存仅作历史保留。
- 只使用分割 mask，关闭未使用的 PyMatting JIT 初始化；既有透明度与 mask 相乘一次，避免透明边缘被重复削弱。
- 测试账号由 `scripts/prepare-e2e.py` 创建，分别保存在忽略的 `.local/e2e-accounts.json` 和 `.local/cutout-e2e-accounts.json`；不使用 demo 或真实用户账号。
- 截图：`.local/screenshots/desktop-cutout.png`、`.local/screenshots/mobile-cutout.png`。

```powershell
backend/.venv/Scripts/python.exe -m pytest backend/tests -q
pnpm build
backend/.venv/Scripts/python.exe scripts/prepare-e2e.py
pnpm test:e2e
```

测试需要本地数据库、Redis、API、worker 和网页已启动。当前 Codex 沙箱直接访问回环数据库会超时，本次集成与浏览器验证通过授权的本机执行环境完成；这不是应用需要修改数据库地址的证据。
