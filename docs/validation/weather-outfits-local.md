# 天气穿搭：本机实现与验证

日期：2026-10-22。本次实现本机规则推荐，未接入 LLM 或实施 NAS 部署。

## 功能

- 衣物新增 7 个可确认字段：厚薄、层次、袖长、裤裙长、风格、防雨、防风。迁移后旧数据均为 unknown；旧客户端 PATCH 不会清除已填写的新标签。
- 每个账号独立保存城市、时段、场合、室内/户外和怕冷/怕热设置。
- 真实 Open-Meteo 城市搜索和逐时体感温度、降雨概率、风速；本地时区、跨午夜及夏令时窗口。预报缓存 1 小时，刷新失败可明确标记使用 6 小时内的缓存；手动天气为独立显式模式。
- 本地有限候选组套，按天气、场合、颜色、收藏、近 7 天穿着和反馈排序；最多 3 套有差异的真实衣物组合，支持上下装或连衣裙模板。缺件及未知属性显示提示。
- 同角色换单品；已穿方案保持快照。整套穿着在事务中再次校验账号、日期、状态和版本，重复请求幂等。
- 已穿方案可填写和修改冷热/喜好反馈。每次从有效反馈重算，冷热与颜色/风格偏好分开。

## 验证结果

- 推荐集成测试 18 项通过，使用专用 PostgreSQL 测试库；覆盖账户隔离、不可用衣物排除、缺件/完整套装、换单品、原子穿着、幂等、过期方案、反馈覆盖、偏好持久化和旧请求兼容。另校验未知上装厚薄不会绕过冷天短下装限制，厚外套也不能补偿严寒时明确过薄的下装。
- 天气测试 10 项通过；覆盖时段范围、跨午夜、半小时时区、夏令时、缓存/旧缓存、缺失或无效天气、手动天气、城市搜索登录要求。网络响应在这些测试中使用可控测试数据。
- 既有衣橱和抠图 25 项回归通过。
- 前端 TypeScript/Vite 构建、后端新模块 Ruff E/F 和 Python 语法检查通过。
- 桌面和手机视口的穿搭浏览器测试 2 项通过（总计 26.9 秒）：真实 API/数据库规则链路，天气使用明确的手动模式；验证图片卡、生成、换件、整套计数、反馈修改与刷新持久化、默认设置、标签保存后洗衣操作不重置，无页面 JS 错误和横向溢出。已查看两张截图。
- 真实外部调用：Shanghai 城市搜索与当天 08:00–20:00 逐时天气成功，返回 live 来源和获取时间。该结果仅证明本机网络与数据解析接通，不代表天气精度或其他地区服务可用性。
- 最终服务重启后的真实浏览器验证：搜索 Shanghai、选择上海、使用城市预报生成 3 套搭配，source=live；页面显示 Open-Meteo 和 CC BY 4.0 署名链接。生成前确认上一份已穿记录及冷热/喜好反馈在重启后仍保留。

后端使用普通 Python 规则，无 GPU 和训练要求。经验厚薄分数不能解释为真实 clo；体感舒适性和偏好改善需要用户实际穿着后验证。旧演示数据属性保持未知，不用推断标签伪造确认结果。

## 复现

```powershell
backend/.venv/Scripts/alembic.exe -c backend/alembic.ini upgrade head
backend/.venv/Scripts/python.exe -m pytest backend/tests -q
pnpm build
backend/.venv/Scripts/python.exe scripts/prepare-e2e.py
pnpm exec playwright test tests/e2e/outfits.spec.ts
```

集成与浏览器测试使用隔离账号及测试库；开发数据、密码、截图和模型仍在 Git 忽略目录。浏览器测试前先运行本机 API、worker 与网页服务；新账号文件为 `.local/outfit-e2e-accounts.json`。
